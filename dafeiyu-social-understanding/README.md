# 大肥鱼群聊理解模块 0.1.0

2026-10-28 部署。仅作用于群 1055067483，使用 Aurabot v1 模块接口；无第三方依赖。

## 行为

监听允许处理的群消息，保留最近15分钟、最多40条消息及引用ID。现有群聊策略与合并逻辑决定是否进入回复；在 prompt 事件中，使用原始对话及最多28条关系记录做一次结构化分析。置信度至少0.5时将分析作为参考附在原始提示后。保留文本、图像和引用编号。不直接发消息，不改工具权限、不覆盖人格卡、不写长期记忆、不主动联网采集。

6秒超时、严格输出校验、单个模型请求并发上限、失败后30秒冷却。宿主 api.ask 不支持取消，因此超时后仍占用分析槽直到请求结束，期间原聊天照常处理。模块卸载后不会注入迟到结果。分析只覆盖进入回复阶段的合并消息；这不是每条消息都独立推理或模型训练。

## 路径和检查

服务器模块：`/srv/dsh/plugins-data/aurabot/modules/dafeiyu-social-understanding/index.mjs`

配置和人格备份：`/srv/dsh/backups/social-understanding-20261028/`

只读状态：`GET http://127.0.0.1:63482/aurabot/api/ext/dafeiyu-social-understanding/status`

固定虚构对话自检：`GET .../selftest`，会调用一次模型，不会发QQ消息。

配置覆盖位置：Aurabot config.json 的 `ext.dafeiyu-social-understanding`，支持 enabled、mode（observe/active）、groupIds。已通过 /aurabot/api/save 将此模块的 ext 设置为 active，仅指定群。观察模式仍调用模型但不补充提示。

## 验证

`node --test test.mjs`：8项测试，覆盖输入隔离、原始内容保留、失败/低置信度/观察模式、超时和并发、卸载、引用关系。

服务器代理上进行了4种虚构场景测试；出现过一次不合结构的输出，按设计丢弃。回放3段历史群聊，均解析成功，约2.4–2.5秒。宿主 api.ask 自检成功约4.4秒。分析不能保证正确，尤其是回复对象判断，因此保留原文并明确分析是可能出错的参考。尚未获得上线后自然对话质量改善的对照证据。

`evaluate.mjs` 是手动模型评估脚本，需在服务器执行；默认虚构场景，设置 REPLAY_FILE 可分析群聊日志的前3段。该脚本不发消息，也不修改记忆。

## 回滚

将模块目录移出 modules，例如移动到 `/srv/dsh/backups/social-understanding-20261028/module-disabled`（先确认目标不存在）。模块扫描器约3秒内卸载；也可在模块管理界面关闭。仅新增此模块的 ext 配置，未修改聊天核心、人格、原有群策略或登录配置，无需恢复整份 config.json。

## 0.2.0：逐轮诊断

新增 `trace-store.mjs`，部署时需与 index.mjs 一起复制。诊断数据写入 `api.dataDir('diagnostics.jsonl')`，不会触发源码热加载。

记录指定群中原策略拒绝接话的原因，以及进入回复阶段的原文、分析状态/结果、回退和生成回复。保留原文最多6000字；日志按约4MB轮转，仅保留当前和上一份，总量约8MB。内存最多保留500条，`GET .../traces` 返回最近150条。日志写入失败不会阻止回复；持久化不可用时退回内存。

回复使用会话与宿主最近600字查询片段关联，多候选或找不到匹配时单独保存为“未关联回复”。这不是确定的宿主turn ID，也不是QQ送达回执。早于本版的聊天不补造诊断。管理后台的人工标注单独保存在管理台数据库，不自动改变人格或训练模型。

`node --test test.mjs trace-store.test.mjs` 验证关联、沉默、未接话、轮转和原有失败保护。
