# 语境注释与表达学习 v0.1

给每个独立角色增加可编辑的理解资料，而不是训练模型权重或自动改人格。模块仅记录该角色已允许处理的聊天；后台通过登录、CSRF和当前角色运行绑定管理。

工作台“理解与学习”支持逐句注释、表情缩略图与解释、重复表达候选确认、角色偏好和世界背景参考，以及召回预览。资料分为“仅来源消息”“当前聊天”“当前角色通用”，默认不会跨群、跨角色使用；私聊注释不能提升为角色通用。通用表达/偏好/背景没有触发词时作为常驻参考，其他资料只在匹配话题或图片标识时召回。可编辑、停用、删除；不是诊断页旧版的只读反馈库。

新消息从模块启用后保留消息编号、引用关系和图片标识，持久化最近200条，接口展示最近100条。以前的聊天文本从现有日志只读加载，可标为当前聊天范围的表达解释，但不能补出不存在的图片。表情预览只代理当前角色已收藏的图像，不允许任意URL或服务器路径。

相同短句至少3次出现、来自至少2位发言者时列为候选，未经人工解释不会用于回复。达到8条有效消息后，系统会自动统计当前聊天最近90分钟的典型句长与emoji频率，作为交流节奏参考，不推断语义或改写性格。不会根据出现次数推断偏好、亲密程度或人格；不会自动语义训练。未来可在此基础上加入有出处的模型提议和人设成长审阅。

每角色最多300条解释；每条1200字；单轮最多6条、参考JSON约6000字。所有注释被标为可能需要纠正的数据，要求以真实对话为准、不照搬口癖、不复述后台资料。图片匹配依赖消息中的MD5或稳定标识，不支持跨压缩、裁剪或重编码后的视觉相似匹配。未看到图或没有人工解释时不承诺能理解梗。当前Gemini订阅网关仅支持文本，该角色的原始图片块会替换为“无视觉内容”提示，结合已确认注释理解，避免模型接口因不支持图片而整轮报错；这不等于新增视觉识别能力。

Aurabot hub 仅扩展 prompt 钩子的 sourceMessageIds 元数据，不改原始对话文本或接话策略；精确注释只匹配本轮来源消息或引用，避免后续并发消息错配。现有群聊理解模块接收人工注释作为附加数据。该模块本身不增加LLM请求、不主动发消息。

数据在各角色 modules-data/social-learning/knowledge/learning.json，文件600，按消息批量写入，退出时刷新；节点突然断电最多丢约1秒的新消息采样。注释修改立即持久化，以revision进行冲突检查，群消息采样不改变注释版本。编辑操作另记入工作台审计。关闭模块后不再注入资料。

验证：`node --test learning.test.mjs`。工作台端另有认证、角色隔离、CSRF和图片访问测试，浏览器验证注释/表情/候选确认/停用/召回预览/手机布局。
