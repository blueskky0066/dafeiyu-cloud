# Claude 角色世界与对话连续性 v0.1

这是现有 QQ / Aurabot 的角色世界适配模块，不是完整 dsh-liketavern 插件。使用自主原创的 ST V2 JSON 角色卡，读取纯文本关键词世界书，在 Aurabot 系统上下文中提供当前世界和状态。用户消息保持原样，没有主动发送消息或额外模型循环。

## 当前设定

原创背景“栖灯港·白灯书院”。Claude 为成年文书，整理旧书、信件和账册；温柔、端庄、有原则，熟悉后有轻微吐槽。角色世界是虚构叙事，直接被问到真实性时坦率解释；现实工具结果、工作进度和群友经历不能捏造。

## 数据与连续性

- character.json：ST V2 角色卡，含6条世界书（1条常驻，其余按本轮关键词召回）。例句仅作为节奏参考。
- index.mjs：在本轮 prompt 钩子选择设定，系统上下文由 api.context 提供，不把角色文本伪装成群友消息。
- world.mjs：北京时间日常节奏、角色卡验证、会话状态读写。状态在4小时内保持，超过后按时段提供初始场景；这是叙事默认值，不意味着离线真的执行活动。
- qq_world_state：模型可保存自己在当前会话里的场景、活动、心情，下一轮读取；不能写其他会话。群友事实仍归现有记忆机制管理。
- 状态保存于 Claude 自己的数据目录 modules-data/claude-world/state，文件名为chatId的SHA256，原子替换，文件600。模块重载后可继续读取。只读预览不写状态。
- 本轮系统上下文有上限；不执行EJS、正则脚本、宏或角色卡扩展。

## 验证与限制

`node --test world.test.mjs`：世界书选择、重载后连续性、会话隔离与过期、实际钩子/工具权限、拒绝附带系统覆盖字段的角色卡。真实Sonnet样本评估与QQ投递是不同验证；不主动向群发送测试消息。情感细腻度与接话效果需要实际群聊持续评估，不能靠单次测试承诺。

完整 Tavern 项目当前要求 Node>=24；线上仍是Node22。上游host bundle与agent预设分开，agent需要会话binding才进入Tavern管线。首版没有安装原生Tavern、Node升级、剧情分支/WAL、BM25记忆、PNG导入或完整ST提示词预设。未来原生接入应先在独立DSH_HOME测试，保留现有QQ身份、文件工具和回滚路径；不要叠加两套人格注入。

停用：维护时向 Claude 本地 Aurabot 的 /aurabot/api/save 提交 {"modules":{"claude-world":{"enabled":false}}}；共栖目前的模块列表只展示状态，没有通用模块开关。旧人格与轻办公模块继续使用。修改 character.json 会触发 Aurabot 热重载；上线前先运行测试并保存旧卡，避免修改共同使用的 Aurabot 源码。
